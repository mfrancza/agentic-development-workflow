# Release: v0.0.1 — Helper-resolution fix

**Issue:** [#505](https://github.com/mfrancza/agentic-development-workflow/issues/505)
**Design:** [docs/design/reusable-workflow-helper-resolution.md](../design/reusable-workflow-helper-resolution.md)

## Summary

Patch release publishing the external reusable-workflow helper-resolution fix
from [#498](https://github.com/mfrancza/agentic-development-workflow/issues/498).

The `v0` reusable workflows previously resolved their helper composite actions
via workspace-relative paths (`uses: ./.github/actions/<name>`). When invoked
from an external consumer repo, the runner's implicit checkout populates the
**caller's** workspace, not this repo's, so those references failed. The fix
introduces a self-checkout at `github.job_workflow_sha` into `_agentic-workflow/`
and rewires every helper reference to that trusted subdirectory.

> **This step cannot be performed by the agent.** `workflow_dispatch` requires
> a human trigger. See [design — Human ratification required](../design/reusable-workflow-helper-resolution.md#human-ratification-required).

### Security decisions to re-confirm before tagging

From [docs/design/reusable-workflow-helper-resolution.md § Human ratification required](../design/reusable-workflow-helper-resolution.md#human-ratification-required):

1. **Decision 1** — `github.job_workflow_sha` is the pinning anchor for the
   helper checkout. The reusable workflows' helpers run at exactly the SHA the
   caller's pin resolved to. No caller-influenceable ref is used.
2. **Decision 4** — Reusable workflows that previously checked out the caller's
   workspace only to resolve local actions will no longer populate the caller
   workspace at all. Only the trusted upstream subdirectory is populated.
3. **Decision 6** — `terraform-ci-reusable.yml` is declared consumer-only
   rather than fixed for external adoption in v0.

### Steps to cut the release

1. Navigate to
   **[Actions → release → Run workflow](https://github.com/mfrancza/agentic-development-workflow/actions/workflows/release.yml)**
2. Set **version** = `v0.0.1`
3. Leave **ref** = `main` (default)
4. Click **Run workflow**
5. Wait for the `release` job to complete (~10 s). It will:
   - Create the annotated `v0.0.1` tag at the current `main` tip (`804e0c6`)
   - Force-update the moving `v0` tag to the same SHA
   - Publish a GitHub Release with auto-generated notes
6. Verify `release-images.yml` fires automatically on the tag push and
   publishes:
   - `ghcr.io/mfrancza/agentic-development-workflow/developer:v0.0.1` and `:v0`
   - `ghcr.io/mfrancza/agentic-development-workflow/reviewer:v0.0.1` and `:v0`
7. Confirm the [GitHub Releases page](https://github.com/mfrancza/agentic-development-workflow/releases)
   shows `v0.0.1` as the latest release with auto-generated notes.
8. Close [Issue #505](https://github.com/mfrancza/agentic-development-workflow/issues/505)
   and unblock [Issue #504](https://github.com/mfrancza/agentic-development-workflow/issues/504)
   (external smoke test, which pins to this tag).
